## Task 9: the email stage

The plan's email stage was blocked on one assumption: that Inbucket messages carry no envelope key. The live capture
(`docs/handoff/2026-10-24-documenso-email-fields.md`) showed the field that works, so the stage was built on it. No time-order or
position matching is used.

- **Signing request**: header `X-Documenso-Envelope-Id` equals the run's envelope id. Its link is `/sign/<token>`.
- **Completion email**: no `X-Documenso-*` header. Its link is `/sign/<token>/complete`. The recipient token joins through
  `Recipient.token` to the envelope, and the join matched the run's envelope.

`src/load/pipeline-email.ts` keeps only completion messages whose token belongs to a run recipient. `evaluatePipeline` reports a
PRODUCT BUG when a recipient's completion email is missing or duplicated. Tests: `tests/unit/pipeline-email.test.ts`. Tokens are
held in memory only; `pipeline-lag.json` holds counts and milliseconds.

Live: `npm run load:documenso-pipeline -- --profile pr` PASS, `pipeline-lag.json` shows `emails: { expected: 22, matched: 22 }`, every stage
missing 0, drain 14 ms, p95 email lag 681 ms. Those numbers are the VM's and are not published (AGENTS.md).
